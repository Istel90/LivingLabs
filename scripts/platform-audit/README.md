# LivingLabs 일일 통합 점검 패키지

버전 1.0.0. 운영 화면과 분리된 검증 패키지이며, 기존 Codex 예약 `risk`가 매번 이 문서와 checks.json의 최신 내용을 읽는다. 새 기능을 배포해도 예약을 다시 만들 필요가 없다.

## 실행

Windows 작업 루트에서 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/platform-audit/run.ps1`로 로컬/외부 HTTP 사전 점검을 실행한다. 기존 Windows 신뢰 인증서 번들을 Node에 추가하며 TLS 검증은 유지한다. 일반 환경은 `node scripts/platform-audit/run.mjs`도 가능하다. `node --test scripts/platform-audit/run.test.mjs`로 응답 판정 회귀 테스트를 실행한다. 추가 npm 설치가 필요 없는 Node 20 이상 패키지이다.

결과는 `output/platform-audit/<UTC 실행 시각>/report.json`에 누적된다. 성공한 HTTP 검사만으로 전체 PASS를 내리지 않는다. 실행기는 HTTP 사전 점검만 자동 수행하며 브라우저 검증은 예약된 Codex 에이전트가 지원되는 브라우저 도구로 수행한다. 독립 실행형 브라우저 테스트 서비스는 아니다.

## 매일 06:00–07:00 Asia/Seoul 운영 절차

1. 06:00–06:10: 실제 시작 시각과 당일 07:00 마감 기록. AGENTS.md, 이 문서, checks.json, 이전 보고서를 읽는다. 기준 침수 화면을 먼저 확인하고 사전 점검 실행. git 변경·최근 배포·서빙 빌드 버전을 기록한다.
2. 06:10–06:30: checks.json의 browser 항목을 외부 우선으로 수행한다. 로컬 결과를 외부 성공으로 대체하지 않는다. 콘솔 오류, 실제 지표 데이터 응답, 계산 결과와 지도를 함께 확인한다.
3. 06:30–06:45: 로컬 공유 기능 회귀, 폭염/WBGT, 순환 지역, 최근 추가 기능을 확인한다. 시간이 부족하면 핵심 침수 분석과 장애 영향 범위를 우선한다.
4. 06:45–06:55: 발견한 장애를 분류하고 허용된 복구 및 영향 범위 재검증. 이미 점검한 정상 항목의 무의미한 반복 대신 미검증 항목을 진행한다.
5. 06:55–07:00: 최초 보고서를 보존하고 같은 디렉터리에 final-report.json과 summary.md 작성. 07:00 이후 새 검사를 시작하지 않는다. 시작이 늦으면 남은 시간만 사용하며 07:00 이후 시작한 실행은 지연 사실을 보고하고 한 시간 늦춰 실행하지 않는다.

각 브라우저 항목은 PASS/FAIL/BLOCKED/NOT_RUN, 환경, 실제 수행 단계, 결과 수치, 증거 파일 또는 도구 관찰 시각을 기록한다. PASS는 실행 증거가 있을 때만 사용한다. 전체 상태는 FAIL이 하나라도 있으면 FAIL, FAIL 없이 BLOCKED/NOT_RUN이 남으면 INCOMPLETE, 모든 필수 항목을 통과했을 때만 PASS이다. 관찰하지 않은 기능과 운영 데이터 쓰기 기능은 미검증 범위로 명시한다.

예약은 06:00 시작 요청이며 07:00까지 실행을 보장하는 운영체제 서비스나 강제 종료 타이머가 아니다. PC·네트워크·실행 환경·인증·사용량이 가용해야 한다. 이 패키지는 부팅, 절전 해제, 상시 감시를 설정하지 않는다. 장애 예방이나 24시간 가용성을 보장하지 않는다.

## 복구 범위

서버/터널 중단은 프로세스·4173 소유자·로그를 확인하고 기존 start-platform.ps1/start-remote-platform.ps1 절차를 검토해 복구할 수 있다. 터널 주소 변경이 필요하면 현재 원격 배포와 대조한다. 진행 중인 배포나 다른 작업과 충돌하지 않게 한다. 기존 접근 제어를 유지하고 비밀값은 보고서에 기록하지 않는다. 승인 실패는 BLOCKED로 보고한다.

데이터 삭제·운영 대안 덮어쓰기·검토 요청 전송·새 공개 경로·무관한 서비스 중단·자동 기능 수정은 하지 않는다. 저장/삭제/요청 등 쓰기 기능은 별도 테스트 환경과 명시적 범위가 없으면 BLOCKED로 기록한다. 서비스 재시작은 영향받는 프로세스만 대상으로 하고 복구 후 외부 분석을 다시 실행한다.

## 새 기능과 유지보수

기능 추가 또는 동작 변경 시 checks.json에 고유 id, 사용자 동작, 기대 결과, 환경 및 쓰기 여부를 포함한 criteria를 추가한다. 기존 검증을 삭제해 실패를 숨기지 않는다. 점검 에이전트는 이전 보고서의 gitHead와 현재 tracked/untracked 변경 중 제품 소스 변경을 검토해 미등록 기능을 보고한다. 자동으로 새 기능의 정확한 의미까지 추론할 수 있다고 가정하지 않는다.

HTTP 검사는 http 배열에 추가한다. 민감한 토큰을 URL에 넣지 않는다. API 형식이 달라지면 run.mjs의 validate 및 회귀 테스트를 함께 갱신한다. checks.json 버전과 이 패키지 버전을 관리한다.

기존 scripts/wbgt/verify-*.py와 scripts/test-*.mjs는 심화 검증 후보이다. 과거 UI 가정·로컬 전용 주소·운영 저장 동작을 포함할 수 있으므로 자동으로 일괄 실행하지 않고 최신 코드와 권한을 검토한 뒤 사용한다.
