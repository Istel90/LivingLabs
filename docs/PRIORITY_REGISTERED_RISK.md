# 등록 지표 조회·지역 맞춤 서버 통합 (2026-09-29)

## 적용

등록 지표의 새 분석은 `/risk-analysis`에 schemaVersion=2로 부문, 지역 코드, 관측/미래, 시나리오, 기간, 격자 단위, 지표 ID/가중치, H/E/V 가중치만 전달한다. 브라우저의 원자료 격자 업로드를 없앴다.

서버 `registered-risk.mjs`는 같은 부문별 구성 목록과 지표 정의를 읽어 소속·가용성을 검증한다. `vworld-data-proxy.mjs`의 내부 조회 처리기를 직접 호출하므로 외부 주소나 임의 파일 경로를 요청으로 받지 않는다. 정적 자료는 기존 정렬 기준에 맞는 부분격자를 추출한 다음 기존 Risk 엔진으로 계산한다. 결과와 사용 입력 격자는 지도 표시·저장본 재현을 위해 응답한다.

`grid-preparation.mjs`는 이전 브라우저의 격자 해석/부분 추출 로직을 그대로 서버로 옮겼다. 조회 시 임의 재투영·재표본화하지 않으며 미정렬 자료는 기존 계산기의 정렬 검사에서 거부한다. TIF 전처리·등록 기준은 그대로 유지한다.

지도 미리보기는 자료 ID 조회를 계속 사용하되, 정적 자료의 `regional=1` 요청은 서버에서 지역 격자 범위로 추출한다. 브라우저의 `cropStaticGridToRegion` 함수는 제거했다. 입력값 전송은 줄었지만 저장 재현용 입력 격자를 응답하므로 서버→브라우저 전송량이 모두 제거된 것은 아니다.

## 호환 범위

- 사용자 업로드 또는 ID가 없는 옛 정의가 포함되면 schemaVersion=1 명시적 입력 경로를 유지한다. 이 경로에서도 계산은 서버에서 수행한다.
- 압축 저장본의 H/E/V 복원은 보존된 입력 격자로 계산한다. 최신 원자료로 바꿔 조회하면 과거 결과 재현이 달라질 수 있어 ID 재조회로 강제 전환하지 않는다.
- 생태계는 지표 0개·공통 UI만 유지한다.
- 외부 배포, 다중 사용자 작업 큐, 모든 지역/시나리오 검증은 이번 범위가 아니다. 기존 요청 크기·격자 수·동시 계산 제한을 유지한다.

## 검증

`RISK_LIVE_TEST=1`로 `npm run test:risk-server`를 실행하면 현재 실제 자료를 이전 커밋의 브라우저 계산과 비교한다. 기존 직접 입력 경로와 새 ID 조회 경로 각각에서 H/E/S/AC/V/Risk 모든 값·결측·통계 일치를 검사한다. 수원 홍수 4,857셀, 폭염 12,095셀, H를 WBGT로 교체한 폭염 12,098셀에서 통과했다. 기준 H/E/V 가중치는 1/2/3이다. 미등록·타 부문 지표 ID는 자료 조회 전 거부한다.

카탈로그/목록 회귀 테스트와 빌드도 확인한다. 실제 브라우저 실행 결과는 완료 보고 및 `output/registered-risk-20260929`에 기록한다. 노션 목록 문서는 코드가 아니라 기준일 스냅샷이며 노션 수정이 실행 설정을 자동 변경하지 않는다.
