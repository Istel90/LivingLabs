기존 화면의 지표 반복 렌더링은 유지하고 입력을 등록 목록으로 교체했다.
지도 표시 설정은 하나의 토글 템플릿과 동작 등록표를 사용한다.
색상·간격·배치·분석식·DB는 유지한다. 2차 적용에서 공통 조회 API를 추가했으며 기존 API도 호환용으로 유지한다.

## 항목을 추가하거나 변경할 때

1. 이미 있는 자료이면 `dataSources`의 ID를 재사용한다. 다른 자료이면 지원되는 연결 방식으로 등록한다.
2. `indicatorCatalog`에 안정적인 지표 ID와 그룹을 등록한다. 동일 자료라도 해석 그룹·방향이 다르면 별도 지표로 정의할 수 있다.
3. 사용할 부문의 `sectorProfiles.indicators`에 지표 ID와 화면 기본값을 추가한다. 숫자 ID는 기존 저장본을 위해 유지하고, 같은 부문 안에서 재사용하지 않는다.
4. `npm run test:priority-registry`와 빌드 검증 후 운영 빌드에 반영한다.
5. 새 처리 방식은 별도 처리기 구현이 필요하다. 목록에 이름만 추가해서 미구현 기능이 생기지는 않는다.

예: `population.elderly` 데이터 연결과 `population.elderly.sensitivity` 지표 정의를 홍수와 폭염이 공유하며 기존 색상·설명·선택 여부의 차이만 각 부문에 둔다.

현재 지원하는 지표 UI 유형은 기존의 `weighted-indicator`, 지도 설정은 `toggle`이다.
그 외 유형은 검증에서 거부한다. 생태계는 사용자 요청에 따라 부문별 지표 목록을 빈 배열로 유지한다. 공통 지도와 네 분류 틀만 표시하며 기존 저장본을 삭제하지 않는다. 공통 카탈로그의 옛 미연결 정의는 현재 목록에서 참조하지 않는다.

## 등록 검증과 호환

없는 지표/연결 참조, 중복 숫자 ID·지표 참조, 미지원 UI 유형·연결 방식, 잘못된 분류·방향·기본값을 검사한다.
기존 저장본의 숫자 ID와 연결 필드는 호환 계층에서 보존한다. 새 지표 ID는 추가 메타데이터이며 저장 형식을 교체하지 않는다.
예전 저장본과 사용자 업로드의 경로 처리도 유지한다. 누락 자료를 0 또는 예시 값으로 대체하지 않는다.

## 전환 범위와 다음 단계

이번 단계는 실제 운영 UI에 구성 목록을 연결하는 작업이다. **아직 프런트엔드가 UI만 담당하는 최종 구조는 아니다.**
Risk 계산은 서버로 이전했다. 저장 호출, 기존 데이터 연결의 재해별 예외, 파일 자료의 지역 맞춤 처리는 호환을 위해 남아 있다.

2차 적용에서 실제 구축 기준과 대조한 격자 계약, TIF 등록 검사, 공통 조회 API를 추가했다. 상세 범위와 운영 방법은 [데이터 인덱스 문서](PRIORITY_DATA_INDEX.md)를 따른다.
좌표계·해상도·픽셀 원점/격자 정렬·NoData·자료형은 고정 계약으로 검사한다. 단위·시기는 존재 여부를 검사하며 지표별 의미·품질 검증은 아직 별도 과제다.
현재 연결 목록에 있는 기존 DB/JSON 서비스를 검증된 TIF 인덱스라고 간주하지 않는다.
등록된 지표의 새 조회는 자료 ID와 지역·시기 조건을 사용한다. 저장본 호환을 위한 옛 경로 필드와 사용자 자료 처리는 남아 있다.
대용량 TIF 전체를 브라우저에 전달하지 않는다. 행정경계는 이미 전처리된 자료의 조회 범위로 사용한다.

분석 계산의 서버 이전 및 기존 분석값 비교 결과는 [서버 계산 문서](PRIORITY_SERVER_RISK.md)에 기록했다.
저장본 비교 기능, 실험실 화면, 신규 운영 화면은 이번 변경 범위에 포함하지 않는다.
