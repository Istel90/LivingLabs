# 지표 데이터 등록과 공통 조회 — 2026-09-29

## 이번에 적용한 흐름

고정 UI → 부문별 지표 목록 → 공통 자료 ID → `/indicator-grid` → 기존 DB/JSON 처리기 또는 검증된 TIF → 기존 형태의 격자 응답.

프런트엔드와 서버는 `shared/data/priority/dataSources.js`의 연결 40개를 공유한다. 서버는 등록된 ID로 조회 방식과 지표 코드를 정한다. 요청자가 임의 파일 경로나 지표 코드를 덮어쓸 수 없다. 5자리 지역 코드와 수원 전용 정적 자료의 범위를 검사한다. 관측/미래·기간·시나리오는 기존 처리기에서 검증한다.

DB/기존 JSON은 기존 결과를 유지하는 호환 연결이다. 이들을 TIF 검사에 통과한 자료라고 표시하지 않는다. 신규 TIF 등록과 UI 지표 추가는 다른 절차이며, 등록된 TIF가 자동으로 UI 목록에 추가되지는 않는다.

## 실제 구축 자료에서 확인한 기준

조사 범위는 `riskmap-core-main/data/processed/hazard`의 595개 TIF 헤더와 부속 메타데이터다. 다른 저장장치의 원자료 전체를 조사한 결과가 아니다.

| 항목 | 계약 |
|---|---|
| 좌표계 | EPSG:5179 |
| 격자 | 100m, 북쪽이 위, 회전 없음 |
| 기준 원점 | X=745900, Y=2068600 |
| 지역 부분자료 | 동일 격자에 정수 셀 단위로 정렬될 때 허용 |
| 자료형 | 단일 밴드 float32 |
| NoData | -9999 |
| 필수 메타데이터 | 지표 ID, 단위, 기간, 동일 grid_spec_id |
| 테스트 자료 | test_only 자료는 등록 거부 |

계약 파일: `shared/data/priority/grid-contract.json`. 기간은 기존 `period`, `period_label`, `year` 필드를 읽어 통일한다. 원본 파일이나 기존 메타데이터를 수정하지 않는다.

**448개 등록, 147개 보류**: 테스트 표시 145개, 격자 ID 불일치 1개, 기간 누락과 격자 ID 불일치가 함께 있는 H11 공간 참조 자료 1개다. H11의 현재 DB 조회를 이 보류 파일로 대체하지 않는다. 등록 수는 자료 추가에 따라 달라질 수 있다.

전국 크기의 격자가 있다고 한반도 전체에 유효값이 있다는 뜻은 아니다. 헤더 검사는 실제 값의 품질, 단위의 의미, 전 영역의 결측률, 지표별 연도 적합성을 보장하지 않는다. 해당 검사는 후속 데이터 품질 단계에서 정해야 한다.

## 자료 추가 절차

1. 기존 전처리에서 위 계약에 맞는 TIF와 `.metadata.json`을 생성한다.
2. 저장 후 `.\.venv-dem\Scripts\python.exe scripts/build-raster-index.py`를 실행한다. 다른 자료 위치는 `--root`와 `--output`을 명시한다. 현재 조회 서버는 기본 hazard 루트와 기본 인덱스만 연결되어 있다.
3. `.runtime-logs/raster-index.json`의 등록/보류 사유를 확인한다. 보류를 강제 승인하거나 요청 시 임의 재투영하지 않는다.
4. 필요한 경우 공통 자료 연결·지표 정의·부문별 목록에 등록하고 해당 처리기의 조회를 검증한다. 새 지표 코드는 기존 처리기의 지원도 필요하다.
5. 데이터 교체 후에는 대상 서버를 정상 재시작해 열린 파일과 캐시를 정리한다. 반복 감시나 자동 예약은 추가하지 않았다.

인덱스는 서버별 절대 루트를 포함한 로컬 산출물이다. GitHub에는 생성 코드와 계약만 저장한다. 다른 PC나 외부 서버에서는 해당 위치의 자료를 검사해 인덱스를 생성해야 한다. 인덱스가 없거나 파일/메타데이터의 크기·수정 시각이 달라지면 TIF 조회를 거부한다. 내용 전체의 SHA-256을 검증한 것은 아니며 `contentHashVerified=false`로 명시한다. 대용량 파일을 매 요청마다 읽지 않는 변경 감지 방식이다.
