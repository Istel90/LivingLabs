## 지표의 의미

**현재 도시환경에서 폭염 대표 기상조건과 장기 평균 일사량을 결합한 시험용 공간 비교 지표**다. 특정 날짜의 실측 WBGT, 실제 시간별 WBGT 시계열, 5년간 WBGT의 평균과는 다르다.

1. ASOS 2021–2025년 6–9월 자료에서 하루 24시간 WBGT를 계산할 수 있었던 날만 사용한다. 각 연도 계절의 완전한 날 비율이 90% 이상이고 5개 연도를 모두 확보한 44개 관측소가 대상이다.
2. 각 관측소·연도의 일최대 추정 WBGT 상위 10%에 해당하는 날을 고르고, 그날들의 09·12·15시 기온·습도·기압·바람 중앙값을 대표조건으로 사용한다.
3. 각 셀에서 가까운 6개 관측소의 대표조건을 거리 제곱의 역수로 보간한다. 기온은 관측소 표고를 보정한 뒤 DEM 표고로 조정한다. 습도는 수증기압을 보간한 뒤 지역 기온에서 다시 계산한다. 기압은 고도차를 반영하며, 바람은 관측 높이를 환산한 10m 상당 풍속을 사용한다.
4. KMAP의 2016-07–2021-06 평균 일사량 중 09·12·15시 자료를 원본 격자에서 가져온다. 투영 좌표에서 가장 가까운 셀을 사용하며 원본 셀과의 거리가 150m를 넘으면 결측 처리한다.
5. KMAP 일사량에 이미 포함된 지형 차폐는 유지한다. NGII 90m DEM은 100m로 보간하여 고도에 따른 기온·습도·기압 조정에 사용한다. 지형 그림자를 한 번 더 곱하지 않는다.
6. 전국 건물 외곽선에 `지상 층수 × 3.3m`를 우선 적용하고, 층수가 없을 때만 기록된 높이를 사용한다. 높이 600m 초과 등 이상값은 임의로 자르지 않고 높이 미확인으로 분류한다.
7. 건물 지붕·그림자는 10m 소격자 중심점에서 계산한다. 20km 작업 구역 바깥 800m의 건물도 포함해 작업 구역 경계에서 그림자가 끊기는 것을 막는다. 경계 버퍼를 넘어가는 그림자는 오류로 처리한다.
8. 2023년 8월 1일의 09·12·15시 태양 위치를 작업 구역 중심에서 계산한다. 직달·산란 성분은 Erbs 식으로 추정한다. 건물 그림자는 직달 성분만 줄이고 산란 성분은 유지한다.
9. 100m 셀의 옥외 면적 중 그늘 비율을 구해 일사량을 조정한 뒤 thermofeel Liljegren WBGT를 계산한다. 세 시간 모두 값이 있는 셀에서 최댓값을 H11로 저장한다.

## 반영하지 않은 환경과 해석 범위

- 수목 그림자는 사용자 결정에 따라 제외했다.
- 건물 주변 국지풍, 도시 표면 온도, 상세 하늘 노출률 및 건물·지표 사이 장파복사 교환은 별도 모형으로 계산하지 않는다.
- 토지피복별 반사율 대신 계산 라이브러리의 기본 지표 반사율 0.45를 사용한다.
- 현재 건물·DEM, 2021–2025 기상 대표조건, 더 이전 시기의 KMAP 일사량을 결합한 합성 조건이다.
- 관측소 사이 기상 보간과 고도 보정은 상세 기온·습도·바람 관측을 대신하지 못한다. 출력 격자가 100m라는 사실만으로 모든 입력과 계산 정확도가 100m 수준이 되는 것은 아니다.
- 이번 검증은 저장·공간 정렬·프로그램 계산 및 기능 검증이다. 현장 WBGT 실측과의 정확도 검증은 아직 수행하지 않았다.
- 미래 WBGT 자료는 만들지 않았고, 미래 모드에서는 H11을 비활성화한다.

홍수 도시침수 30년 자료는 269개 지역 중 28개 지역에서 유효 원자료가 없다. 해당 지표를 0점 위험으로 채우지 않는다. 이 지역에서 기본 분석은 사용 가능한 저지대 지형 H와 E/V 자료로 실행된다. 따라서 기능은 같아도 분석에 실제 사용한 지표와 결과 셀 수는 지역별로 다르다. 실행 완료 문구와 지표 선택 목록을 함께 확인해야 한다.

WBGT 지도 색상은 전국 공통 정규화 기준이다. 같은 색 구간에 들어가는 셀은 원값이 달라도 비슷하게 보일 수 있다. WBGT 단독 H 표시에는 지역별 실제 최소–최대 ℃ 범위를 함께 보여준다. Risk 계산용 정규화 범위는 지도 표시 때문에 지역별로 바꾸지 않는다.

## 검증과 재현

- `scripts/wbgt/build_national_spatial_wbgt.py`: 전국 계산, 작업 구역 단위 이어받기, 전국 병합.
- `scripts/wbgt/test_spatial_wbgt.py`: 그림자 방향·높이·작업 구역 경계·미확인 높이·고도 보정 수치 검사.
- `scripts/wbgt/verify_national_wbgt_data.py --served`: 269개 지역의 저장 파일·서버 값·공통 격자 일치 검사.
- `scripts/wbgt/verify-national-platform.py`: 기본 홍수·폭염 및 WBGT 단독 H 선택 후 실제 Risk 버튼 실행.
- `scripts/wbgt/verify-platform-workflows.py`: 지도 레이어, 설정 내보내기, 대안 전환·복원, 실패·재실행, 잘못 정렬된 입력 거절, 실제 필지 기반 실천권역 도출.
- `scripts/wbgt/verify-platform-modes.py`: 현재·미래 모드 전환, 미래 H11 비활성화, 현재 모드 복귀.
- `scripts/wbgt/verify-platform-parcels.py`: 전국 모든 지역의 홍수 및 WBGT 폭염 분석, 5개 지도 레이어, 실제 필지 교차를 통한 실천권역 도출, 결과 내보내기.
- `scripts/wbgt/verify-platform-exports.py`: 수원·제주의 홍수/폭염 PNG 파일 생성, 파일 내용·크기·지역명 확인. 배경지도는 외부 연결 상태에 따라 빠질 수 있다.
- `scripts/wbgt/verify-platform-drafts.py`: 수원·제주·인천 전체의 홍수/폭염 로컬 임시 저장·복원과 축약 서버 형식의 저장·복원. 저장 전후 H/E/V/Risk 배열을 해시로 대조한다.
- `scripts/wbgt/verify-platform-weights.py`: 수원·제주에서 홍수와 폭염의 H 지표 가중치를 1.0에서 1.5로 바꿔 이전 결과 해제·재실행·결과 변화 확인.
- `scripts/wbgt/verify-exported-risk.py`: 기본 8개 사례와 가중치를 변경한 4개 사례의 실제 내보낸 입력값으로 H/E/V/Risk를 독립 재계산. 중복을 포함한 95,296개 유효 결과 셀, 최대 절대 차이 약 2.98×10⁻⁸.
- `scripts/wbgt/test-analysis-serialization.mjs`: 희소/밀집 배열, 0과 결측, 과거 저장 형식의 복원 검사.

서버 저장 검사는 브라우저 요청을 시험 응답으로 처리하여 저장 payload와 복원을 확인했다. 실제 운영 Supabase에 시험 기록을 생성하지 않았으며, 원격 서버의 권한·정책·응답 성능이 검증되었다는 뜻은 아니다. JSON 저장 형식은 [Supabase JSON 문서](https://supabase.com/docs/guides/database/json)를 참고했다. 과거에 이미 빈 객체로 저장된 희소 원본 값은 복구할 수 없으며 해당 원자료를 다시 불러와 분석해야 한다.

Risk의 H/E/V 통합은 기존 가중 기하평균 정의를 유지한다. 0에는 기존 최소값 0.0001을 적용한다. 구성요소 안에서 일부 지표가 결측인 셀은 그 셀에서 유효한 지표의 가중치를 다시 합산한다. 구성요소 자체가 계산되지 않는 셀은 종합 Risk에서 제외한다. 이번 수치 검사는 이 정의의 구현 일치 여부를 확인했으며 통합식의 정책적 타당성을 검증한 것은 아니다.

브라우저 실행 결과의 최종 건수와 미통과 여부는 `validation-summary.json` 및 개별 JSON 기록에 저장한다. 화면이 열렸다는 사실만으로 통과 처리하지 않고 실제 결과 셀과 원본 자료 응답을 확인한다. 외부 배경지도 타일 연결은 네트워크 상태에 따라 달라지며, 분석 격자와 필지의 로컬 자료 검증과 구별한다.

전국 실행 검사는 기본 홍수·폭염 설정과 WBGT 단독 H 설정을 대상으로 한다. 모든 지표 조합·가중치·미래 연도·사용자 업로드 형식을 전수 검사한 것은 아니다. 공통 동작의 동등성과 지역별 자료 연결을 확인하는 검사이며, 현장 모형 정확도나 정책 판단을 대신하지 않는다.

Python 3.12 실행 환경과 프로젝트의 `.tools/python312-wbgt` 의존성을 사용한다. 예전 Python 3.13 가상환경의 바이너리 모듈을 섞지 않는다. 계산식·입력 자료를 변경할 때는 새 버전과 새 출력 폴더를 만들고, 검증한 뒤 공통 H11 경로를 교체한다. 수원 전용 분기나 예전 ASOS 전용 결과로 돌아가는 자동 대체 경로를 추가하지 않는다.

실천지구의 계획행정·시설지원·시민실천 분류는 기존 화면에 표시된 시연 규칙 v1이다. 이번에 동작과 필지 교차를 검증했으며, 분류 기준의 타당성 검증까지 완료했다는 뜻은 아니다.

## 보관 구조

- `active-tiles.json`: 전국 병합에 사용한 387개 타일과 각 SHA-256. 초기 작업에서 남은 마스크 미적용 캐시는 현재 결과에 포함하지 않는다.
- `reproducibility/`: 계산·검증 스크립트 및 변경한 플랫폼 소스의 보관본. 재실행은 원래 프로젝트 폴더와 원본 데이터·로컬 PostGIS가 있는 환경에서 한다.
- `validation/`: 지역별 API 검증, 전국 브라우저 검사, 저장·복원·수치 대조 기록.
- `checksums.json`: 전국 최종 결과와 주요 보관 파일의 SHA-256.
- `README.md`: 이 문서의 복사본. 전국 파일이 어느 방식으로 만들어졌고 플랫폼에서 어떻게 사용되는지 함께 보관한다.

큰 격자의 저장 형식은 `__analysisGrid: sparse-v1`(희소 원본 Map) 또는 `dense-sparse-v1`(결측이 많은 밀집 배열)이다. 후자는 전체 배열 길이와 유효 셀 인덱스·값을 보관한다. 기록되지 않은 셀은 0이 아니라 결측이다. `analysisSerialization.js`가 두 형식과 이전 숫자 키 형식을 복원한다.

`tile_boundary_diagnostics.json`에는 20km 계산 구역 경계의 인접 셀 값 차이를 기록했다. 경계에서 평균 절대 차이는 가로 약 0.0436℃, 세로 약 0.0426℃였고, 구역 내부는 각각 약 0.0439℃와 0.0421℃였다. 광역적인 경계 이음새를 점검한 진단이며 국지적 정확도 검증을 뜻하지 않는다.
