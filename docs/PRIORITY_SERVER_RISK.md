# Risk 계산 서버 이전 — 2026-09-29

## 적용 범위

로컬 개발용 4173의 공통 홍수/폭염 화면에 적용했다. UI 디자인, 계산식, 가중치와 저장 형식은 유지한다. 기존 돌아가기 문구 변경도 유지한다. 외부 사이트 배포는 별도다.

현재 흐름:

1. 브라우저가 기존 자료 ID 조회로 지표와 지도 미리보기 격자를 불러온다.
2. 선택된 지표의 정규화 격자, 분류, 방향, 가중치, 격자 좌표를 `POST /risk-analysis`에 전달한다. 유효 값은 셀 번호/값 쌍으로 전달한다.
3. 서버가 요청을 검사하고 별도 Worker 스레드에서 H/E/민감도/적응역량/V/Risk를 계산한다.
4. 브라우저는 반환된 결과 격자를 복원해 기존 지도와 결과 화면에 표시한다. 실패 시 오류를 표시하며 브라우저 계산으로 우회하지 않는다.

`riskmap-core-main/scripts/risk-engine.mjs`는 이전 화면의 계산 함수를 그대로 추출했다. `risk-service.mjs`는 검증/요청 처리, `risk-worker.mjs`는 계산 실행과 결과 전송을 담당한다. 프런트엔드 `riskClient.js`에는 전송·응답 복원만 남긴다.

## 호환과 제한

- 원래의 결측 처리, 그룹별 가중 평균, 적응역량 방향 반전, V의 0.5 혼합, H/E/V 가중 기하평균, 상위 10% 임계값을 유지한다.
- 대안별 실행 번호를 응답 후에도 확인해 오래된 응답이 새 대안을 덮어쓰지 않도록 한다.
- 기존 저장본은 재계산 없이 표시할 수 있고 새 계산 결과도 같은 형태로 저장한다. 이번 검증에서는 운영 저장본을 수정하지 않았다.
- H/E/V 구성 레이어가 생략된 압축 저장본은 서버에서 해당 레이어만 복원한다. 저장된 Risk 격자·통계·실천권역 후보는 유지하며, 복원 중 대안을 바꾸면 오래된 응답을 적용하지 않는다.
- 요청당 최대 64MB, 지표 64개, 격자 800만 셀, 입력 유효 값 합계 200만 개. 기준 초과 시 명시적으로 거부한다. 실제 수원 입력은 제한 내에서 검증했다. 전국/큰 행정구역 전 범위를 검증한 것은 아니다.
- 서버 계산은 한 번에 한 건, 추가 요청은 429로 재시도를 안내한다. 계산 제한 시간 90초, 브라우저 요청 제한 120초다. 다중 사용자용 작업 큐는 아직 구현하지 않았다.
- 외부 전달 설정은 `/risk-analysis`의 계산용 POST만 추가 허용한다. 기존 다른 API의 쓰기 차단은 유지한다. 외부 사이트 반영·실행 검증은 미완료다.

**데이터 조회와 정규화 격자의 지역 맞춤 처리는 아직 브라우저에 남아 있다.** 이번 작업은 계산 엔진 이전이다. 최종적으로 ID·지역·기간·가중치만 서버에 보내도록 하려면 조회/정렬까지 서버 작업으로 합쳐야 한다. 현재 서버는 전달받은 격자를 계산하며 원자료 ID와의 진위 대조까지 하는 구조는 아니다.

## 검증

`npm run test:risk-server`로 이전 커밋 `d2a3c5c`의 실제 함수를 독립 실행해 셀별 배열과 요약값을 비교한다. 밀집/희소 격자, 결측, H-only, 격자 불일치, 숫자 문자열 호환, HTTP/Worker 왕복, 잘못된 입력 차단을 확인한다.

실제 데이터 비교는 `RISK_LIVE_TEST=1` 환경 변수로 같은 테스트를 실행한다. 수원 기준 H/E/V 가중치 1/2/3에서 아래 세 경우의 H/E/S/AC/V/Risk 전체 배열, 유효 셀, 결측, 요약 통계가 이전과 완전히 일치했다.

| 구성 | 지표 | 유효 셀 |
|---|---:|---:|
| 홍수 기본 | 8 | 4,857 |
| 폭염 기본 | 12 | 12,095 |
| 폭염 H를 WBGT로 교체 | 12 | 12,098 |

브라우저에서 정확한 홍수 기준 화면을 먼저 열고 새 대안의 실제 Risk 실행과 Risk/Hotspot 전환을 확인했다. 이후 폭염 기본 및 H01을 해제하고 H11을 선택한 분석도 완료했다. 위와 같은 유효 셀 수를 확인했고 검증 탭 콘솔 오류는 없었다. 기존 사용자의 열린 탭은 수정하지 않았다. 화면 증거는 `output/server-risk-20260929/flood.png`, `heatwave.png`, `wbgt.png`에 보관한다.

반복 점검 예약을 추가하지 않았다. 기존 하루 한 번 점검 목록에 서버 Risk 수용 기준을 추가했다.
