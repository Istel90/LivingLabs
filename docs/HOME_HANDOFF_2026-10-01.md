독립 확인은 `git clone --branch codex/registry-driven-ui https://github.com/Istel90/LivingLabs.git LivingLabs-latest`로 새 폴더에 받는다.

## 집에서 시작할 순서

1. Dropbox 새 인계 폴더를 **오프라인 사용 가능**으로 내려받고 모든 파일의 동기화가 끝났는지 확인한다. 인계 자료를 작업용 별도 폴더에 복사한다.
2. Python으로 `python check_package.py --package "인계폴더"` 실행. 전체 전송 해시와 269지역 결과 검사가 통과해야 한다.
3. 집의 기존 채팅에 `04_집채팅에붙여넣기.txt`를 전달한다. 집 저장소의 브랜치·커밋·미커밋 파일·최근 작업 기록을 먼저 읽고 보존한다.
4. `python compare_home.py --package "인계폴더" --repo "E:\40_LocalPython\LivingLabs"` 실행. 읽기만 하며 변경/덮어쓰기하지 않는다. `both_differ_review`는 양쪽이 달라 비교가 필요하다. `home_change_preserve`는 회사 기준 이후 집에서 바꾼 내용일 수 있으므로 보존한다.
5. `01_company_source.zip`은 **비어 있는 별도 비교 폴더**에 해제한다. 기준 커밋 이력을 확인하고 회사 변경을 집 작업 브랜치에 3방향 병합한다. 충돌을 파일별로 해결한다. 소스 ZIP 전체 덮어쓰기, reset --hard, 실행 중인 서버/DB 강제 교체는 하지 않는다.
6. 데이터 ZIP도 새 작업 폴더에 해제한다. 기존 9/30 원자료 ZIP은 Dropbox 회사전달 위치에서 재사용한다. 현재 2021 결과 검토와 2025/공원/보행도로/건물 PK 원본 확보를 구분해 진행한다.
7. 코드 병합 후 기존 집 환경에서 의존성·설정 확인, `npm run test:risk-server`, `npm run test:practice-area-server`를 실행한다. 이전 계산 비교 검사는 기준 커밋 `6142d46` 이력이 필요하다.
8. 로컬 빌드 `npm run build:unified`는 `/internal-tools` 기준으로 `pages-dist/internal-tools`를 만든다. 4173 소유 프로세스를 확인한 뒤 집의 기존 방식으로 시작/필요 시 해당 서버만 재시작한다. 홍수 기준 화면과 폭염에서 실제 데이터 요청·Risk·실천권역·저장본 복원을 검증한다. 공동 DB에 시험 자료를 쓰거나 공개 배포하는 검증은 별도 작업으로 다룬다.
